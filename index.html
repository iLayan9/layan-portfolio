How I work

  1. 01

    Question it

    I use the product myself and check every requirement against the logic and the rules before designing it.

    Example Ten interviews showed the real problem in bill splitting wasn't the math. It was asking friends to pay back.

    See it in Qatiah →
  2. 02

    Map it

    Every status, path and edge case is listed before the first screen, so nothing is designed by accident.

    Example Every insight from the research mapped to the screen that answers it, before the design system was set.

    See it in Qatiah →
  3. 03

    Build it on a system

    Screens are composed from shared components and tokens, then reviewed with the people who will use them.

    Example One token structure behind three brands, two languages and two themes.
